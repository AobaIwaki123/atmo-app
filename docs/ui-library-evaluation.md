# UI コンポーネントライブラリ評価レポートと技術選定

本ドキュメントは、気圧監視・気象病対策アプリ `atmo-app` におけるUIコンポーネントライブラリの検証結果、手触りの評価、および最終的なアーキテクチャ選定理由を記録した技術知見です。

---

## 1. 検証の背景と要件

* **目的**: 急激な気圧変化（大気圧の崖）を検知し、頭痛や自律神経過緊張を未然に防ぐための個人用ダッシュボード。
* **要件**:
  - ダークモード基調（暗所や頭痛時でも目に優しい配色）。
  - 直近48時間の気圧推移のスムーズな可視化。
  - 現在の気圧値、急変トレンド（3h変動）、警戒レベルの直感的な把握。
  - **方針**: 「素朴な機能でどこまでいけるか評価し、差がなければ依存が最も軽いもの（外部依存最小）を採用する」。

---

## 2. 検証したライブラリと評価サマリー

独立したPoCブランチを作成し、同一のバックエンドAPI（`https://atmo.aooba.net/api/v1/pressure`）を接続して手元で動作比較を実施しました。

| ライブラリ / 手法 | GitHub Stars | 検証スコープ | 評価結果・手触り | 採否判定 |
|---|---|---|---|---|
| **fl_chart**<br>(`imaNNeo/fl_chart`) | 7.5k+ | 48時間気圧推移の動的ベジェ曲線グラフ、ツールチップ | **極めて高評価**。<br>滑らかな曲線、下部グラデーション、現在時刻のドットマーカー、タップ時の正確な数値ポップアップが優れており、静的PNG画像とは比較にならない質感を実現。 | **採用** |
| **shadcn_ui**<br>(`nank1ro/flutter-shadcn-ui`) | 1.5k+ | Tailwind/Radix UIライクなモノトーンカード、バッジ、Lucideアイコン | **外装として高評価**。<br>繊細な境界線とタイポグラフィ、余白の美しさは好印象。ただし標準機能で同等の質感を再現できたため、依存追加を避けるため見送り。 | 参考保留 |
| **GetWidget**<br>(`ionicfirebaseapp/getwidget`) | 4.8k+ | `GFCard`, `GFBadge`, `GFListTile`, `GFLoader` による総合UI | **不採用**。<br>アバターやバッジの装飾が野暮ったく、今回のミニマルなダークテーマの世界観に合致しなかった。「フォントは良いがそれ以外が微妙」との判断で却下。 | **却下** |
| **Skeletonizer**<br>(`Milad-Akarie/skeletonizer`) | 1.8k+ | 既存UIを包むだけのゼロ工数シマースケルトンローディング | **高評価**。<br>API待機中の骨組みシマー体験は非常に優秀。ただしAPI取得が極めて高速（キャッシュ済みJSON）なため、第1フェーズでの依存最小化を優先して将来拡張枠へ。 | 将来拡張 |
| **Flutter標準機能**<br>(Material 3 + Container / Stack / LayoutBuilder) | なし<br>(SDK組込) | 微細グラデーション、状態連動ボーダー、自作気圧スケールバー | **最高評価**。<br>外部パッケージ追加ゼロでありながら、グラデーション・枠線・気圧位置ピン付きスケールバーを組み合わせることで、サードパーティ製を凌駕する洗練された計器盤を実現。 | **採用** |

## 3. 最終採用スタック

方針「最も依存が軽いもの」を徹底した結果、**外部依存は `fl_chart` の1つのみ**に絞り込みました。

```text
[ atmo-app 画面構成 ]
  │
  ├─ 1. 警告バナー (Flutter標準)
  │      └─ 急変検知時のみ赤系透過コンテナで表示
  │
  ├─ 2. 計器盤カード (Flutter標準)
  │      ├─ 背景: 微細な斜めダークグラデーション (Slate 800 -> Gray 900)
  │      ├─ 境界線: 状態連動の微細ボーダー (安定: Cyan / 警戒: Red)
  │      ├─ メイン数値: 特大気圧値 (1011.5 hPa) + トレンド矢印 (Icons.trending_up)
  │      └─ 気圧スケールバー: 990〜1030 hPa 内での現在位置を光るピンで表示
  │
  └─ 3. 48時間気圧推移チャート (fl_chart)
         └─ 滑らかな動的ベジェ曲線 + 下部透過グラデーション + タップ時ツールチップ
```

---

## 4. 得られた技術的知見

1. **Flutter標準描画のポテンシャル**:
   - サードパーティの重厚なUIキットを無理に導入しなくても、`Container` のグラデーションと `Stack` の位置計算だけで、車載メーターや高級オーディオのようなリッチなカードを容易に構築できる。
2. **依存最小化のメリット**:
   - 外部ライブラリを `fl_chart` のみに限定したことで、Flutterバージョンアップ時の互換性崩壊リスクをほぼゼロに抑えられた。
3. **グラフの動的化の費用対効果**:
   - バックエンド生成の静的PNG画像と比較して、クライアント側で `fl_chart` を用いて描画した動的グラフは、アプリ全体のネイティブ感と操作体験を劇的に引き上げる。
